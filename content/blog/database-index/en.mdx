## A smaller search space

An index maintains an additional access structure so a lookup can avoid examining every row. The tradeoff is storage and extra work on writes.

## Try the lookup

This model searches unique integer keys from 1 through 1,024. A sequential scan stops at the target; binary search repeatedly halves a sorted key array. Move the slider to compare the actual number of key comparisons.

## From arrays to databases

![An index connects a query to a data page.](/index-path.svg)

```sql
CREATE INDEX orders_customer_idx ON orders (customer_id);
SELECT * FROM orders WHERE customer_id = 42;
```

The demo illustrates search-space reduction, not a database B-tree implementation. Real indexes navigate pages, may require heap lookups, and depend on caching, selectivity, and the query planner. A scan can still be preferable when a query reads much of a table.

## What to measure

Compare query plans, pages read, and elapsed time on your workload. Do not translate the comparison count above directly into a latency speedup.
