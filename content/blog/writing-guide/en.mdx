## Make the workflow explicit

<Steps>
<Step>

### Write

Create an English MDX article with validated metadata. Add the Chinese translation when it is ready.

</Step>
<Step>

### Verify

Run content validation, type checking, and a production build. Review interactive examples against the claims in the prose.

</Step>
<Step>

### Publish

Open a pull request. Merge after required checks pass; GitHub Actions exports and deploys the site.

</Step>
</Steps>

## Keep details available

<Accordions type="single" collapsible>
  <Accordion title="What belongs in a reusable component?">
    Put interactive behavior and calculations in React/TypeScript modules. Keep
    the article focused on the explanation, assumptions, and interpretation.
  </Accordion>
  <Accordion title="What does the static search index include?">
    Published titles, descriptions, headings, and prose extracted by Fumadocs.
    Drafts and text generated only by interactive components are excluded.
  </Accordion>
</Accordions>

<Callout title="A measurement is not a guarantee" type="warn">
  State workload assumptions and limits next to the result. A tiny browser
  demonstration does not establish production database performance.
</Callout>
