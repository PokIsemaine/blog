# 16. 摘要与 TLDR 自包含

TLDR、摘要和开头的浓缩总结必须让读者在不读后文的情况下理解文章的核心论证。至少说明：讨论的问题及现有方案的缺口、核心 insight 或判断、具体贡献，以及证据支持的结果和限制。博客不要求机械套用论文摘要格式；没有技术贡献时，用文章的核心发现或方法替代。

摘要中不得引入正文尚未解释的关键概念、缩写或项目名。贡献名称必须能被问题、insight 和实现方式解释，不能出现读者无法接上的概念跳跃。摘要中的 claim 必须能在正文找到对应证据，不能比正文结论更强或范围更宽。

TLDR 最多 120 个语义单位。每个英文/数字词或中日韩字符各计 1，混合语言按同一口径累加；`npm run validate` 会检查 `<TLDR>` 块。超限时优先删除背景介绍、重复限定和次要实现细节，不要压掉问题、缺口、insight、贡献或证据边界。

审核时指出摘要缺失的论证环节、未解释的名称、超出正文证据的表述，以及超过 120 个语义单位的内容，并给出具体补写、收窄或删减建议。
